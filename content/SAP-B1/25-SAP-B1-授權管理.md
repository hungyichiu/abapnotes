# SAP License Manager：機碼查詢、更新與故障排除

## 前言

SAP Business One 的授權管理是每位 B1 顧問的必備技能。不論是新客戶上線、系統移機、授權到期、還是使用者數量調整，都會觸碰到授權的操作流程。這個流程看起來簡單，但有幾個細節如果沒做到位，就會導致客戶無法登入，電話直接打來。

本文完整說明 B1 授權的構成要素、查詢方式、更新標準流程，以及授權過期或更新失敗的故障排除方法。

---

## 授權的構成要素

要理解 B1 授權，需要先認識幾個關鍵識別碼：

| 識別碼 | 說明 | 在哪裡查看 |
|--------|------|------------|
| **安裝號碼（Installation Number，INSTNO）** | B1 安裝時由 SAP 核發，代表這套系統 | 關於 SAP B1 畫面 |
| **系統號碼（System Number）** | SAP 官方網站上的客戶識別號碼，和安裝號碼共同組成唯一授權 | 關於 SAP B1 畫面 |
| **硬體碼（Hardware Key）** | 由主機硬體特徵產生的唯一碼，用來綁定授權到特定主機 | LCC（License Control Center）|
| **主機名稱（Host Name）** | 執行 B1 Server 的主機名稱 | LCC 或作業系統 |

這四個要素缺一不可。SAP 在核發授權檔（.slm 或 .xml 格式）時，會將安裝號碼和系統號碼寫入授權檔；而硬體碼則用來驗證授權只能在指定主機上使用。

### 實際範例

以下是一台開發測試環境的授權資訊（已去識別）：

> [!info]
> 版本：SAP Business One 10.0 (10.00.201) FP 2208 (64-bit)
> 安裝號碼：0021257243
> 系統號碼：000000000850636987
> 硬體碼：X2081805255
> 主機名稱：DEVSERVER01

> **為什麼硬體碼很重要？** 當客戶需要移機（把 B1 Server 搬到新主機），硬體碼會改變，原有授權就會失效。必須事先向 SAP 申請新主機的授權，才能完成移機。

## 授權查詢方法

B1 的授權查詢有兩個主要入口：

### 方法一：透過 B1 Client 查看

登入 B1 後，前往：

> [!info]
> 說明 > 關於 SAP Business One

這個畫面可以看到：
- 版本號碼
- 安裝號碼（INSTNO）
- 系統號碼
- 目前使用的授權類型（Professional / Limited）

適合快速確認已掛載的授權內容。

### 方法二：透過 SLD（SAP License Manager）查看

SLD 是 B1 的系統管理後台，帳號資訊如下：

> [!info]
> 帳號：B1SiteUser
> 密碼：安裝 B1 時設定的系統架構密碼（SSMS 密碼）

SLD 提供更完整的授權管理功能，包含：
- 目前掛載的授權詳細內容
- 每種授權類型的數量和已指派數量

### 方法三：透過 LCC（License Control Center）查看硬體碼

LCC 是最常用來查詢硬體碼（Hardware Key）和匯入授權的工具：

> [!info]
> 路徑：B1 Server 安裝目錄 > License > LCC

LCC 的主要功能：
- **查詢** Hardware Key（向 SAP 申請授權時必填）
- **查詢** 目前授權版本（Project Manager 需要此資訊申請授權）
- **匯入** 授權檔案（.slm / .xml）

## 授權更新流程：申請 → 下載 → 更新 → 驗證

### Step 1：取得 Hardware Key

在 LCC 中查詢目前主機的 Hardware Key，記錄下來。

### Step 2：向 SAP 申請授權

登入 SAP 官方入口網站（通常由 SAP Partner 的 PM 操作）：

> [!info]
> 網址：SAP Support Portal / License Key Request
> 所需資訊：安裝號碼、Hardware Key、申請原因（新購/展延/增購授權數）

測試授權（Development License）的申請相對簡單，正式授權需要有對應的銷售合約。

### Step 3：下載授權檔

SAP 核發授權後，可在授權申請頁面下載 `.slm` 或 `.xml` 格式的授權檔。

授權檔只包含安裝號碼（INSTNO），尚未包含完整授權資訊：

### Step 4：更新前的準備（關鍵步驟）

**這個步驟最容易被省略，卻最容易造成問題：**

在匯入新授權之前，必須先取消所有使用者的授權指派：

> [!info]
> B1 > 管理 > 授權 > 授權管理員 > 取消所有使用者的指派

如果跳過這個步驟直接更新，B1 在識別授權時可能讀取到舊的授權資訊，導致使用者無法正常登入。

### Step 5：匯入新授權

在 LCC 中：
1. 點選「匯入授權檔案」
2. 選擇下載的授權檔
3. 確認授權資訊（安裝號碼、系統號碼、到期日）
4. 完成匯入

### Step 6：重啟相關服務（視情況）

部分情況下，匯入授權後需要重啟 Service Layer，才能讓授權生效：

```bash
# 進入 Service Layer 安裝目錄
cd "C:\Program Files\SAP\SAP Business One ServerTools\ServiceLayer"

# 重啟 Service Layer
b1s.bat restart
```

### Step 7：重新指派授權並驗證

1. 在 B1 的「授權管理員」中，重新指派授權給所有使用者
2. 請使用者重新登入，確認功能正常
3. 確認授權到期日已更新至正確日期

授權掛載成功後，在授權欄位可看到完整的安裝號碼（INSTNO）與客戶號碼：

## 授權類型說明

B1 的授權以使用者類型區分：

| 授權類型 | 縮寫 | 說明 |
|----------|------|------|
| **Professional** | P | 完整功能授權，可存取所有模組 |
| **Limited Financial** | LF | 限制版財務授權，僅可操作財務相關模組 |
| **Limited Logistics** | LL | 限制版物流授權，僅可操作採購/銷售/存貨 |
| **Starter Package** | SP | 小型企業簡化版，功能和使用者數有限制 |

## 測試授權的申請與管理

在開發測試環境或專案導入期間，顧問經常需要申請「測試授權」（Development License / Test License）。

測試授權的特點：
- 有固定到期日（通常 90 天，可申請展延）
- 和正式授權分開管理
- 可申請在不同硬體（如顧問筆電）上使用

### 測試授權到期的處理

如果測試授權到期，客戶或顧問無法登入 B1：

1. 確認到期日（在 LCC 或「關於 SAP B1」畫面查看）
2. 向 SAP 申請展延（需提供申請原因）
3. 下載新授權，依標準更新流程操作

## 常見陷阱

1. **移機時沒有預先申請授權**
   - 主機搬遷後，Hardware Key 改變，舊授權完全失效
   - 解法：移機計畫確定後，立刻向 SAP 申請新主機的授權

2. **更新授權前沒取消指派**
   - 導致使用者無法登入，或登入後出現異常
   - 解法：一律先取消指派，再更新授權，再重新指派（這是不可省略的 SOP）

3. **授權數量不足導致部分使用者無法登入**
   - B1 是同時上線授權（Concurrent），超過授權數的使用者會被拒絕登入
   - 解法：在授權管理員中確認「最大可用數量」vs「目前已指派數量」

4. **搞混安裝號碼和系統號碼**
   - 申請授權時，這兩個號碼都需要提供，且不能搞混
   - 解法：建議每個客戶都建立一份授權資訊表，記錄這四個識別碼

5. **測試授權到期沒注意，直接影響客戶操作**
   - 解法：在行事曆上設定到期前 2 週的提醒，提早申請展延

## 實作提醒

- **每個客戶維護一份授權資訊表**：記錄版本號、安裝號碼、系統號碼、Hardware Key、主機名稱、授權到期日，以及聯絡的 SAP Partner 窗口
- **更新授權的 SOP 要文件化**：「取消指派 → 更新授權 → 重啟服務（如需要）→ 重新指派 → 驗證登入」，這個順序不能靠記憶
- **測試授權集中管理**：如果同時維護多個客戶的測試環境，建議建立一張「測試授權 LIST」，追蹤各環境的到期日和目前狀態
- **移機計畫要提早處理授權**：授權從申請到核發需要時間，建議至少提前 2 週申請，不要等到移機當天才處理
- **Service Layer 重啟的影響**：重啟 Service Layer 會中斷目前所有的 B1 連線，需要在非上班時間或知會所有使用者後進行
